# LabOps 复试展示讲解提纲

## 1. 一句话介绍

LabOps 是一个面向高校实验室的智能设备预约与运维管理平台，主要解决实验设备预约混乱、设备状态不透明、故障处理缺少闭环、实验室运行数据难以统计的问题。

## 2. 项目背景

高校实验室设备通常由学生、教师和管理员共同使用。传统管理方式可能依赖纸质登记、微信群通知或人工协调，容易出现预约冲突、设备故障无人跟踪、管理员无法掌握设备利用率等问题。

因此我设计了 LabOps，把实验室设备管理做成一个数据看板型中后台系统，通过设备台账、预约审批、故障报修、维修工单和数据分析，形成完整的实验室运营闭环。

## 3. 核心功能

系统主要包含四条主线：

1. 设备管理：维护设备编号、分类、实验室、负责人、状态和健康评分。
2. 预约管理：学生或教师提交预约，教师或管理员审核，系统校验时间冲突。
3. 报修运维：用户提交报修，管理员创建维修工单，处理完成后验收关闭。
4. 数据分析：统计设备利用率、预约趋势、故障分布和平均维修时长。

## 4. 角色权限

系统设计了四类角色：

- 学生：查询设备、提交预约、提交报修。
- 教师：审核预约、查看统计数据。
- 实验室管理员：管理设备、处理报修、创建工单、查看看板。
- 系统管理员：管理用户、角色、权限和基础配置。

这个权限模型采用 RBAC 思路，前端用于控制菜单和按钮，后端通过 FastAPI 依赖项校验接口权限。

## 5. 技术选型

前端使用 Vue3 和 ECharts。Vue3 适合构建中后台单页应用，ECharts 用于展示趋势图、环形图、柱状图等数据可视化内容。

后端使用 FastAPI。FastAPI 开发效率高，类型提示清晰，自动生成 OpenAPI 文档，适合前后端分离项目。

数据库使用 PostgreSQL。系统中用户、角色、设备、预约、报修、工单之间关系明确，适合使用关系型数据库建模。

部署使用 Docker Compose，把前端、后端和数据库拆成独立容器，方便本地启动和演示。

## 6. 数据库设计思路

数据库围绕设备生命周期设计：

- 用户、角色、权限用于登录和鉴权。
- 实验室、设备分类、设备表用于维护设备台账。
- 预约表记录设备使用申请和审核结果。
- 报修表记录用户提交的故障。
- 工单表记录维修处理过程。
- 维护记录表沉淀设备历史。

这些表之间通过外键关联，可以支撑从预约到报修再到数据分析的完整业务链路。

## 7. 接口设计思路

接口采用 REST 风格，统一以 `/api/v1` 作为前缀。主要接口包括：

- `/auth`：登录和当前用户信息。
- `/dashboard`：首页看板统计。
- `/devices`：设备管理。
- `/reservations`：预约管理。
- `/repair-reports`：报修管理。
- `/work-orders`：维修工单。
- `/users`、`/roles`：系统管理。

后端返回统一 JSON 结构，前端通过 API 模块统一请求。

## 8. 演示流程

复试现场可以按下面顺序演示：

1. 打开首页看板，展示设备总数、今日预约、待处理报修和趋势图。
2. 进入设备管理，展示设备状态和设备详情。
3. 以学生身份提交一个设备预约。
4. 以教师或管理员身份审核预约。
5. 模拟设备故障，提交一条报修记录。
6. 管理员创建维修工单并完成处理。
7. 回到数据分析页面，说明预约和维修数据如何沉淀为管理指标。

## 9. 项目亮点

- 不是简单 CRUD，而是包含预约审批和维修工单两个业务闭环。
- 数据库实体关系完整，便于讲解 ER 建模。
- 首页看板视觉效果强，适合第一眼展示项目完成度。
- 技术栈覆盖前端、后端、数据库和容器化，工程链路完整。
- 后续可扩展硬件数据采集、消息通知、移动端预约和智能预测维护。

## 10. 可能被问到的问题

### 为什么选择 FastAPI？

FastAPI 支持类型提示和自动接口文档，开发效率高，适合前后端分离项目。对于复试项目来说，它既能快速实现业务接口，也能清楚展示接口规范。

### 如何避免预约冲突？

提交预约和审核预约时都需要检查同一设备在目标时间段内是否存在已通过或待审核的冲突预约。数据库层面可以通过查询时间区间重叠实现，业务层再返回明确提示。

### 设备利用率如何计算？

可以用指定时间范围内设备被预约并实际使用的时长除以设备可用总时长。例如一台设备一天可用 8 小时，如果预约使用了 4 小时，则当天利用率为 50%。

### 报修和工单为什么分开？

报修表示用户发现问题并提交故障，工单表示管理员安排维修处理。两者分开后，可以更清楚地表达从故障发现到维修关闭的流程，也方便统计受理效率和维修效率。

### 后续如何扩展？

后续可以接入物联网设备状态采集、消息通知、移动端预约、智能排班和故障预测，让系统从管理平台升级为更完整的智慧实验室平台。
