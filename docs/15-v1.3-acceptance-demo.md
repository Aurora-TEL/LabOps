# LabOps v1.3 验收与演示手册

本文档面向 LabOps v1.3 的复试展示和最终集成验收。v1.3 的核心变化是：系统不再只是管理员视角的统一后台，而是支持普通用户、设备负责人、管理员登录后进入不同前端，并在后端按角色控制权限和数据范围。

## 1. v1.3 验收重点

| 分类 | 验收项 | 通过标准 | 当前记录 |
| --- | --- | --- | --- |
| 登录分流 | 不同账号进入不同页面 | `ordinary01` 进入 `/ordinary`，`owner01` 进入 `/owner`，管理员进入 `/dashboard` | 已实现 |
| 前端菜单 | 角色侧边栏隔离 | 普通用户只见自助台，设备负责人只见负责人工作台，管理员见完整后台 | 已实现 |
| 后端权限 | 越权请求拦截 | 普通用户不能审批、建工单；设备负责人不能处理非本人负责设备 | 已实现 |
| 数据范围 | 查询结果按角色收窄 | 普通用户只看本人预约/报修；设备负责人只看负责设备相关数据 | 已实现 |
| 设备负责人保护 | 禁止转移负责人 | `device_owner` 更新设备时不能修改 `manager_id` | 已实现 |
| 容器验证 | 测试与构建在 Docker 内完成 | 后端测试、前端构建、迁移和种子数据均在容器内执行 | 已验证 |
| 宿主机清洁 | 不残留依赖和构建产物 | 无 `node_modules`、`dist`、`.venv`、`__pycache__`、`.pytest_cache` | 已检查 |

## 2. 3-5 分钟演示路径

建议按“三个身份看同一个系统”的方式演示，比单纯逐页介绍更能体现项目完整性。

| 时间 | 页面 | 演示动作 | 讲解重点 |
| --- | --- | --- | --- |
| 0:00-0:30 | 登录页 | 展示四个演示账号卡片 | 系统已经具备登录、JWT 和 RBAC |
| 0:30-1:20 | 普通用户自助台 | 使用 `ordinary01 / labops123` 登录，展示可预约设备、我的预约、我的报修 | 普通用户只能完成预约和报修，不进入管理员后台 |
| 1:20-2:10 | 普通用户自助台 | 新建预约或提交报修 | 数据写入 PostgreSQL，刷新后仍可查询 |
| 2:10-3:10 | 设备负责人工作台 | 退出后使用 `owner01 / labops123` 登录，展示负责设备、预约审批、维修工单 | 设备负责人只处理自己负责设备，不看全平台数据 |
| 3:10-4:00 | 管理员后台 | 使用 `admin / password` 登录，进入完整运营首页、设备、预约、报修、分析、系统设置 | 管理员视角是全局运营后台 |
| 4:00-4:40 | Swagger / 测试说明 | 打开 `http://localhost:8000/docs`，说明后端权限依赖和 403 越权拦截 | 前端隐藏按钮是体验，后端鉴权才是安全边界 |
| 4:40-5:00 | Docker 总结 | 展示容器状态和验证命令 | Vue3 + FastAPI + PostgreSQL + Docker Compose，全流程容器化 |

## 4. 权限边界讲解

复试现场可以用这一段解释：

> LabOps 不是把所有用户都做成管理员，而是按真实实验室角色拆分。普通用户只关心预约和报修，所以登录后进入自助台；设备负责人只负责自己名下设备，所以登录后进入运维工作台；管理员才进入完整运营后台。前端负责菜单和页面分流，后端通过 JWT、权限编码和数据范围过滤保证安全，绕过前端直接调接口也会返回 403。

## 5. 容器验证清单

所有命令都应在 Docker 或 Docker Compose 中完成，不在宿主机安装项目依赖。

```bash
docker compose build --progress=plain
docker compose up -d --force-recreate
docker compose ps
docker compose exec backend alembic upgrade head
docker compose exec backend python -m app.db.seed
docker compose run --rm -e PYTHONDONTWRITEBYTECODE=1 backend pytest -p no:cacheprovider
docker build --target build -t labops-frontend-build-check ./frontend
```

本轮已完成的验证记录：

- `docker compose build --progress=plain`: 通过。
- `docker compose up -d --force-recreate`: `postgres`、`backend`、`frontend` 均 healthy。
- `docker compose exec backend alembic upgrade head`: 通过。
- `docker compose exec backend python -m app.db.seed`: 通过。
- `docker compose run --rm -e PYTHONDONTWRITEBYTECODE=1 backend pytest -p no:cacheprovider`: `17 passed, 2 warnings`。
- `docker build --target build -t labops-frontend-build-check ./frontend`: 通过，Vite 仅提示 ECharts chunk 体积优化建议。
- `ordinary01` 和 `owner01` 登录冒烟验证通过。

## 7. 下一步扩展方向

如果老师追问后续计划，可以这样回答：

- 接入消息通知，让预约审批、报修派工有站内信或邮件提醒。
- 接入 IoT 设备状态采集，自动更新设备在线、运行、故障状态。
- 增加维护计划和备件库存，让运维闭环更接近真实实验室。
- 增加审计日志，记录审批、派工、状态变更等关键操作。
- 增加移动端预约入口，方便学生和老师在实验室现场使用。
