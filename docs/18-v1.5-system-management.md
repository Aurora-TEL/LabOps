# v1.5 系统管理与 RBAC 治理中心

## 目标

v1.5 将“系统设置”从展示型入口升级为可演示的系统管理模块，重点说明 LabOps 不是只在前端做页面分流，而是在后端通过用户、角色、权限、审计共同形成治理闭环。

## 功能范围

- 用户管理：管理员查看用户列表，按关键词、状态、角色筛选用户。
- 状态管理：管理员可启用、停用、锁定用户。
- 角色分配：管理员可为用户分配角色。
- 角色权限矩阵：展示系统角色、用户数量和权限点。
- 审计追踪：用户状态和角色变更写入审计日志。
- 运行态安全：后端解析 token 后回表校验用户状态，并重新计算角色权限。

## 后端接口

新增系统管理接口统一挂载在 `/api/v1/system`：

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/system/summary` | 系统管理摘要 | `user:manage` 或 `role:manage` |
| GET | `/system/users` | 用户分页列表 | `user:manage` |
| PATCH | `/system/users/{user_id}/status` | 修改用户状态 | `user:manage` |
| PUT | `/system/users/{user_id}/roles` | 覆盖式分配用户角色 | `role:manage` |
| GET | `/system/roles` | 角色列表与权限点 | `role:manage` |
| GET | `/system/permissions` | 权限点清单 | `role:manage` |

关键规则：

- 当前用户不能停用或锁定自己。
- 最后一个启用状态的 `system_admin` 不能被停用。
- 最后一个启用状态的 `system_admin` 不能被移除系统管理员角色。
- 用户被停用后，旧 token 访问接口也会返回 403。
- 用户状态变更、角色变更写入 `audit_logs`。

## 前端页面

`/system` 页面升级为三个 Tab：

- 用户管理：用户筛选、状态切换、角色勾选与保存。
- 角色权限：角色列表、用户数量、权限点矩阵。
- 操作审计：展示最近审计记录。

页面仍保持浅色科技中后台风格，复用现有 `panel`、`table`、`source-badge`、`mini-button` 等样式。

## 演示价值

v1.5 适合在复试中回答“权限怎么做”“管理员怎么管”“前端隐藏菜单是否安全”等问题：

- 前端根据角色权限控制入口和菜单。
- 后端接口使用 `require_permissions` 做强校验。
- token 解析后回表校验用户状态，停用用户立即失效。
- 管理动作写入审计日志，可追踪谁改了什么。
