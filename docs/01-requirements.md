# LabOps 需求文档

## 1. 项目概述

LabOps 是一个面向高校实验室场景的智能实验室设备预约与运维管理平台。系统围绕“设备怎么预约、设备是否可用、故障如何闭环、运行数据如何展示”四个核心问题展开，提供统一的设备台账、预约审批、故障报修、维修工单和数据分析能力。

项目采用数据看板型中后台系统形态，UI 参考智能制造运营平台、ERP 管理后台和设备运维平台，整体风格为浅色科技风：左侧导航、顶部状态栏、指标卡片、趋势图、环形图、状态列表和实时告警信息。该项目适合用于考研复试展示，既能展示前后端分离开发能力，也能体现需求分析、数据库建模、接口设计和 Docker 部署等完整工程流程。

## 2. 建设背景

高校实验室通常存在多类贵重仪器和共享设备，例如显微镜、3D 打印机、传感器实验台、嵌入式开发套件、网络测试设备等。这些设备往往被不同学生、教师和课题组共同使用。如果仅依赖线下登记表、微信群通知或人工协调，容易出现以下问题：

- 预约信息分散，用户无法实时判断设备是否可用。
- 设备状态不透明，故障、维护、停用信息传递滞后。
- 报修流程缺少闭环，无法跟踪故障从提交到修复的全过程。
- 管理员缺少数据支撑，难以分析设备利用率和故障高发设备。
- 复试展示中很难用一个小项目体现完整的业务链路和工程能力。

LabOps 将实验室设备管理抽象为一个轻量级的“智能制造式运营后台”，通过看板化界面展示设备运行态势，通过流程化功能管理预约和运维。

## 3. 项目目标

### 3.1 业务目标

1. 建立统一的实验设备查询和预约入口。
2. 展示设备在线、空闲、使用中、维护中、故障等状态。
3. 建立预约申请、审核、取消、完成的完整流程。
4. 建立故障报修、工单派发、维修处理、验收关闭的运维闭环。
5. 通过数据看板展示预约量、设备利用率、故障率、维修效率等指标。

### 3.2 技术目标

1. 使用 Vue3 实现前端中后台管理界面。
2. 使用 ECharts 实现趋势、分布、排名等可视化图表。
3. 使用 FastAPI 实现 REST API 服务。
4. 使用 PostgreSQL 设计关系型业务数据模型。
5. 使用 Docker Compose 编排前端、后端和数据库容器。

### 3.3 展示目标

1. 在复试中能清晰说明项目需求来源和用户痛点。
2. 能展示业务流程、角色权限、数据库 ER 图和接口设计。
3. 能演示一个完整链路：提交预约、审核预约、设备状态变化、提交报修、处理工单、看板数据更新。
4. 能说明技术选型原因和系统扩展方向。

## 4. 用户角色

| 用户 | 典型诉求 | 主要使用场景 |
| --- | --- | --- |
| 学生 | 快速找到可用设备并预约，遇到故障能提交报修 | 查询设备、提交预约、查看预约、提交报修 |
| 教师 | 掌握实验室使用情况，审核学生预约 | 审核预约、查看设备状态、查看统计数据 |
| 实验室管理员 | 管理设备台账，处理预约和维修事务 | 维护设备、处理报修、创建工单、查看看板 |
| 系统管理员 | 管理账号、角色、权限和基础数据 | 用户管理、角色管理、权限配置、系统字典 |

## 5. 业务范围

### 5.1 本期范围

- 首页数据看板。
- 设备台账管理。
- 设备预约管理。
- 报修与维修工单管理。
- 实验室和设备分类管理。
- 用户、角色和权限基础设计。
- 数据分析页面。
- Docker 本地开发环境。

### 5.2 暂不实现范围

- 微信小程序或移动端 App。
- 硬件设备实时采集接入。
- 复杂审批流引擎。
- 真实短信、邮件、企业微信通知。
- 多校区、多租户、财务收费等高级功能。

这些功能可以作为复试答辩中的后续扩展方向。

## 6. 核心业务场景

### 6.1 设备预约

学生进入系统后，按照实验室、设备分类、设备状态筛选可用设备，查看设备详情和可预约时间段，填写用途后提交预约申请。教师或实验室管理员审核后，系统更新预约状态。预约通过后，该时间段内设备被占用，其他用户无法重复预约。

### 6.2 设备报修

用户发现设备异常后，在设备详情页提交报修信息。系统生成报修记录，管理员根据故障情况创建维修工单并安排处理。工单完成后填写维修结果，管理员验收关闭。系统记录故障类型、处理时长和维修结果，用于后续数据分析。

### 6.3 运行看板

管理员进入首页即可查看实验室运行态势，包括设备总数、在线设备数、今日预约数、待处理报修、设备利用率趋势、设备状态分布、预约状态分布和最新告警。看板用于快速判断当前实验室是否处于健康运行状态。

## 7. 非功能需求

| 类型 | 要求 |
| --- | --- |
| 易用性 | 后台界面清晰，关键操作路径不超过 3 步 |
| 可维护性 | 前后端分层清晰，接口文档和数据库文档完整 |
| 可扩展性 | 设备类型、状态、故障类型可通过字典扩展 |
| 安全性 | 使用登录认证和角色权限控制关键接口 |
| 可部署性 | 支持 Docker Compose 一键启动开发环境 |
| 可演示性 | 首页看板必须有足够数据呈现，适合现场讲解 |

## 8. 成功标准

项目达到以下状态即可作为复试展示版本：

- 能通过 Docker Compose 启动 PostgreSQL、FastAPI 和 Vue3 前端。
- 前端至少包含首页看板、设备管理、预约管理、报修工单、数据分析页面。
- 后端至少提供设备、预约、报修、工单和看板统计接口。
- 数据库至少覆盖用户、角色、实验室、设备、预约、报修、工单、维护记录等核心表。
- 能演示一条从设备预约到数据看板变化的完整业务链路。
