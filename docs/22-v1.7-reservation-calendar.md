# v1.7 预约日历与设备占用视图

## 模块定位

v1.7 将预约管理从列表审批升级为时间可视化。用户可以先查看设备占用，再选择空闲时段提交预约；设备负责人审批时可以看到同一设备的已确认占用；管理员可以从全局角度查看一周内预约排程。

## 功能范围

- 预约页支持列表、周历、设备时间轴三种视图。
- 日历接口按 `start_time`、`end_time`、`device_id` 查询预约事件。
- 可用性接口按设备和起止时间检查已确认预约冲突。
- 已确认预约作为硬占用，待审核预约作为排程事件展示。
- 普通用户只查看本人预约事件，设备负责人只查看本人负责设备，管理员查看全局。
- 前端冲突提示用于提升体验，后端审批与数据库排他约束仍是最终边界。

## 新增接口

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/v1/reservations/calendar` | 查询预约日历事件 | `reservation:view_self` 或 `reservation:view_all` |
| GET | `/api/v1/reservations/availability` | 检查指定设备时段是否可用 | `reservation:create`、`reservation:approve` 或 `reservation:view_all` |

### 日历查询

参数：

- `start_time`: ISO datetime，必填
- `end_time`: ISO datetime，必填
- `device_id`: UUID，可选

规则：

- `end_time` 必须晚于 `start_time`。
- 单次查询跨度不超过 62 天。
- 查询重叠条件为 `reservation.start_time < end_time` 且 `reservation.end_time > start_time`。

### 可用性检查

参数：

- `device_id`: UUID，必填
- `start_time`: ISO datetime，必填
- `end_time`: ISO datetime，必填
- `ignored_reservation_id`: UUID，可选

返回：

- `available`: 是否没有已确认冲突
- `conflict_count`: 冲突数量
- `conflicts`: 冲突预约事件

## 角色边界

| 功能 | 普通用户 | 设备负责人 | 实验室管理员 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 查看预约日历 | 本人预约 | 负责设备预约 | 全局 | 全局 |
| 查看设备占用时间轴 | 本人相关/演示占用 | 负责设备 | 全局 | 全局 |
| 创建预约前检查冲突 | 是 | 可用于审批判断 | 是 | 是 |
| 审批预约 | 否 | 负责设备 | 是 | 是 |

## 答辩讲解点

v1.7 体现的是预约业务的时间维度治理：列表能说明“有哪些预约”，日历和设备时间轴能说明“什么时候被谁占用”。前端可以提前提示冲突，但最终仍由 FastAPI service 和 PostgreSQL 排他约束兜底，避免并发审批造成同一设备同一时段重复占用。
