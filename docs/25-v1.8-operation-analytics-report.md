# v1.8 运营分析报表

## 模块定位

v1.8 将数据分析页从静态图表升级为运营分析报表。它把设备、预约、报修、工单、维护台账等业务数据汇总成可解释的指标，用于展示平台的数据沉淀和管理决策能力。

## 功能范围

- 新增独立接口 `GET /api/v1/analytics/operation-report`。
- 前端 `/analytics` 支持按日期范围加载报表。
- 报表展示 KPI、预约趋势、报修趋势、预约状态分布、故障类型排行、维护类型占比、设备健康排行。
- API 不可用时自动切换演示数据，保障复试演示连续性。
- 数据范围延续 RBAC：管理员看全局，设备负责人只看负责设备范围，普通用户不进入完整分析页。

## 指标口径

| 指标 | 口径 |
| --- | --- |
| 设备平均健康分 | 当前范围内可见设备 `health_score` 平均值 |
| 预约占用时长 | 已确认预约 `end_time - start_time` 总小时数 |
| 估算利用率 | 已确认预约时长 / 设备数 / 天数 / 8 小时 |
| 平均维修时长 | 已关闭报修 `closed_at - created_at` 平均小时数 |
| 工单闭环率 | 已完成或已关闭工单 / 范围内工单总数 |

## 后端接口

```text
GET /api/v1/analytics/operation-report?start_date=2026-06-01&end_date=2026-06-30
```

权限：

- `analytics:view`

返回：

- `kpis`
- `reservation_trend`
- `repair_trend`
- `reservation_status`
- `fault_types`
- `maintenance_types`
- `device_health`

## 前端页面

页面结构：

1. 顶部筛选栏：日期范围、近 7 天、近 30 天、刷新、导出。
2. KPI 区：设备健康、预约占用、估算利用率、维修时长、闭环率。
3. 图表区：预约报修趋势、预约状态分布、故障类型、维护类型、健康排行。
4. 明细区：设备健康分和风险状态。

## 答辩讲解点

可以这样说明：

> v1.8 重点体现系统的数据价值。前面的预约、报修、工单、维护记录不是孤立功能，它们会沉淀成运营指标。管理员可以通过分析页看到设备健康、预约占用、故障类型、维护结构和工单闭环情况，从而判断哪些设备资源紧张、哪些设备维护风险更高。
