# LabOps v1.3 角色工作台与权限范围

## 1. 演示账号

| 身份 | 用户名 | 密码 | 登录后页面 | 核心能力 |
| --- | --- | --- | --- | --- |
| 普通用户 | ordinary01 | labops123 | `/ordinary` | 查看可预约设备、提交预约、取消本人预约、提交报修、查看本人报修 |
| 设备负责人 | owner01 | labops123 | `/owner` | 查看本人负责设备、维护设备状态、审批相关预约、创建与推进维修工单 |
| 实验室管理员 | labadmin01 | labops123 | `/dashboard` | 进入完整运营后台，管理设备、预约、报修和工单 |
| 系统管理员 | admin | password | `/dashboard` | 拥有全局管理、用户角色和系统配置能力 |

## 2. 前端分流规则

登录成功后，前端根据 `/auth/me` 返回的角色自动进入不同工作台：

- `ordinary_user` 和兼容角色 `student` 进入普通用户自助台。
- `device_owner` 进入设备负责人工作台。
- `lab_admin`、`system_admin` 和兼容角色 `teacher` 进入完整运营后台。

普通用户和设备负责人不再展示完整后台侧边栏，也不能通过手动输入后台地址进入非本角色页面。

## 3. 后端权限范围

后端不只依赖前端隐藏按钮，而是在接口层校验权限：

- 普通用户只能查看本人预约和本人报修。
- 普通用户不能创建设备、审批预约、创建工单或推进工单。
- 设备负责人只能查看和维护 `manager_id` 指向自己的设备。
- 设备负责人只能审批本人负责设备的预约。
- 设备负责人只能为本人负责设备的报修创建和处理工单。
- 设备负责人不能通过设备更新接口修改 `manager_id`。
- 管理员保留全局数据和全局操作能力。

## 4. 本轮验收重点

建议答辩演示按账号切换展示：

1. 使用 `ordinary01` 登录，确认直接进入“我的实验预约”，只出现预约和报修能力。
2. 使用 `owner01` 登录，确认直接进入“设备负责人工作台”，只出现负责设备、审批和工单能力。
3. 使用 `admin` 登录，确认进入完整运营后台。
4. 在 Swagger 或接口测试中验证越权请求返回 403。
5. 全部验证使用 Docker Compose 或 Docker build，不在宿主机安装依赖。
