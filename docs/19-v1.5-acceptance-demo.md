# v1.5 验收与演示手册

## Docker 验证

所有验证都在容器内完成，不在宿主机执行 `pip install`、`npm install`、`pytest` 或 `npm run build`。

```bash
docker compose up -d
docker compose exec backend alembic upgrade head
docker compose exec backend python -m app.db.seed
docker compose run --rm -e PYTHONDONTWRITEBYTECODE=1 backend pytest -p no:cacheprovider
docker build --target build -t labops-frontend-build-check ./frontend
```

## 页面验收

1. 使用 `admin / password` 登录。
2. 进入 `/system`。
3. 查看顶部系统管理指标：用户总数、启用用户、系统角色、权限点。
4. 在“用户管理”Tab 中筛选用户、切换状态、保存角色。
5. 在“角色权限”Tab 中查看角色权限矩阵。
6. 在“操作审计”Tab 中查看系统管理和业务动作日志。
7. 使用 `ordinary01 / labops123` 或 `owner01 / labops123` 登录，确认看不到系统设置入口。

## 接口验收

管理员登录：

```bash
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"password\"}"
```

管理员读取系统管理数据：

```bash
curl http://localhost:8000/api/v1/system/summary \
  -H "Authorization: Bearer <admin-token>"

curl http://localhost:8000/api/v1/system/users \
  -H "Authorization: Bearer <admin-token>"

curl http://localhost:8000/api/v1/system/roles \
  -H "Authorization: Bearer <admin-token>"
```

普通用户负向验收：

```bash
curl http://localhost:8000/api/v1/system/users \
  -H "Authorization: Bearer <ordinary-token>"
```

预期返回 403。

## 讲解词

“v1.5 我把系统设置升级成了权限治理中心。管理员能查看用户、角色、权限点，也能停用用户和调整用户角色。更关键的是，后端不会只信 JWT 里的旧权限，而是在解析 token 后回数据库校验用户状态并重新计算权限，所以用户被停用后旧 token 也会失效。系统管理动作还会写入审计日志，这样答辩时可以讲清楚权限边界和可追踪性。”
