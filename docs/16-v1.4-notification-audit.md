# v1.4 消息通知与操作审计

## 目标

v1.4 在 v1.3 多身份工作台基础上，补齐“业务动作有反馈、关键操作可追踪”的演示闭环。

- 普通用户：提交预约、提交报修后，可在顶部通知中心看到审核和处理结果。
- 设备负责人：收到待审核预约、待处理报修和工单状态提醒。
- 管理员：在系统设置页查看最近操作日志，用于说明后端审计能力。

## 后端范围

新增数据库表：

- `notifications`：用户通知，包含接收人、标题、内容、分类、关联业务对象、已读状态。
- `audit_logs`：操作审计，包含操作者、动作、资源类型、资源 ID、摘要、详情和结果。

新增接口：

- `GET /api/v1/notifications`：当前登录用户通知列表。
- `GET /api/v1/notifications/summary`：当前登录用户未读数量。
- `PATCH /api/v1/notifications/{notification_id}/read`：标记单条通知已读。
- `PATCH /api/v1/notifications/read-all`：全部标记已读。
- `GET /api/v1/audit-logs`：管理员查看审计日志。

新增权限：

- `notification:view`
- `notification:update`
- `audit_log:view`

业务事件接入：

- 创建预约：通知设备负责人，写入 `reservation.create` 审计。
- 通过/驳回预约：通知申请人，写入 `reservation.approve` / `reservation.reject` 审计。
- 取消预约：通知设备负责人，写入 `reservation.cancel` 审计。
- 提交报修：通知设备负责人和管理员，写入 `repair.create` 审计。
- 创建/更新/完成工单：通知相关人员，写入 `work_order.*` 审计。

## 前端范围

- 顶部栏新增通知铃铛、未读角标和通知面板。
- 通知中心优先读取后端接口，接口不可用时回退演示数据。
- 系统设置页新增“最近操作日志”区域，管理员可讲解审计能力。
- 保持 v1.3 登录后按身份直达不同页面的分流逻辑。
