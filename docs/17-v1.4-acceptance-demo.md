# v1.4 验收与演示手册

## 演示主线

1. 使用 `ordinary01 / labops123` 登录，系统进入 `/ordinary`。
2. 打开顶部通知铃铛，说明普通用户只能看到自己的预约和报修通知。
3. 普通用户新建预约或提交报修，说明后端会产生通知和审计记录。
4. 使用 `owner01 / labops123` 登录，系统进入 `/owner`。
5. 设备负责人审核预约、创建或推进工单，通知会推送给相关用户。
6. 使用 `admin / password` 或 `labadmin01 / labops123` 登录，进入完整后台。
7. 打开“系统设置”，展示最近操作日志，说明关键业务动作可追踪。

## 必验接口

```bash
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"ordinary01\",\"password\":\"labops123\"}"
```

拿到 token 后验证：

```bash
curl http://localhost:8000/api/v1/notifications \
  -H "Authorization: Bearer <token>"
```

管理员验证审计日志：

```bash
curl http://localhost:8000/api/v1/audit-logs \
  -H "Authorization: Bearer <admin-token>"
```

普通用户访问审计日志应返回 403，用于说明后端权限不是只靠前端隐藏菜单。

## 页面验收点

- 顶部栏通知铃铛展示未读数量。
- 点击铃铛后出现通知面板，可查看通知分类、内容、已读状态。
- 点击“标为已读”或“全部已读”后，未读数同步下降。
- 管理员系统设置页展示最近操作日志。
- 普通用户和设备负责人仍然只看到各自工作台，不进入完整管理后台。

## 答辩讲解词

“v1.3 解决了不同身份进入不同工作台的问题，v1.4 进一步补上了业务闭环。预约、报修和工单不是静态列表，而是会触发消息通知，并且关键动作会写入审计日志。这样既能让普通用户知道申请进度，也能让设备负责人及时处理任务，管理员还能追踪系统内发生过什么操作。”
